<objective>
## Goal
Add an OpenFeature-based feature-flag client to control-plane core, backed by a CUSTOM Unleash provider (no official OpenFeature→Unleash Python provider exists per the brief), with the single `tier=enterprise` gate as the primary use case.

## Purpose
v6 Phase 0 W0.3 requires OpenFeature SDK + Unleash so every enterprise-only capability sits behind ONE `tier=enterprise` check at the subagent boundary — never forked code paths. The brief flags a real gap: OpenFeature has no official Unleash provider for Python (Unleash/unleash#3912 open). So we implement a custom `AbstractProvider` wrapping the Unleash Python client, with a no-network in-memory default for solo/CI.

## Output
control_plane.core.flags package (OpenFeature client + custom Unleash provider + in-memory default), unit tests, self-host Unleash compose, learnings doc.
</objective>

## AC-7: Flag documented as config-gate, NOT authorization boundary
Given a feature flag is not an entitlement check
When docs/learnings/feature-flags.md and the flags __init__ docstring are read
Then both state PROMINENTLY: `tier-enterprise` is a rollout/config gate, NOT the security boundary. ## AC-8: UnleashProvider enforces TLS + safe token + fail-closed on bad response
Given the provider talks to Unleash over the network
