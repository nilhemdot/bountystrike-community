<objective>
## Goal

Replace the existing `pgvector/pgvector:pg17` Postgres image with a custom
BountyStrike image that bundles all three Phase 1 extensions — pgvector (HNSW
semantic dedup), vectorscale (DiskANN at scale), and pg_search (ParadeDB BM25
hybrid search) — then activate those extensions in `00_extensions.sql` and add
the Phase 1 DiskANN and BM25 index migrations.

## Purpose

The current stack ships `pgvector/pgvector:pg17` which provides only `vector`.
`vectorscale` and `pg_search` are NOT included in that image — ParadeDB dropped
pgvectorscale from its published bundle, and the pgvector image has no BM25.
Phase 1 deterministic verifier and semantic dedup both depend on all three
extensions being loadable. This plan unblocks every subsequent Phase 1 plan
by establishing a single, reproducible Postgres image that can load all three
extensions with a single `docker compose up`.

## Output

- `infra/docker/Dockerfile.postgres-bs` — custom Postgres 17 image built from
  `postgres:17-alpine`, installs pgvector, vectorscale, and ParadeDB pg_search
  from source/packages in one layer
- `infra/docker/docker-compose.yml` — `postgres` service switched to
  `bs-postgres:pg17` built from `Dockerfile.postgres-bs`
- `infra/sql/00_extensions.sql` — Phase 1 extensions activated (uncommented
  `vectorscale` + `pg_search` lines)
- `infra/sql/10_phase1_vectorscale_indexes.sql` — DiskANN index on
  `findings.embedding` column (replacing HNSW at >500K vectors threshold)
- `infra/sql/11_phase1_paradedb_search.sql` — BM25 index on `findings` table
  for hybrid keyword + vector search
- `docs/learnings/database-patterns.md` — encoding of `CREATE EXTENSION
  vectorscale` trap, custom-image rationale, and boto3/R2 note for 01-02
</objective>
