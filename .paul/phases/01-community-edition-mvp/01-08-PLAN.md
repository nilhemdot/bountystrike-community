<objective>
## Goal
Ship a single **one-line installer** (`scripts/install.sh`) that takes a fresh
Ubuntu/Hetzner host from clone → running stack with zero interactive prompts:
ensure Docker, seed `.env` from `.env.example` with auto-generated infra secrets,
generate the RS256 scope keypair, `docker compose up -d --build`, wait for
healthchecks, and print next-steps. Idempotent and offline-testable.

## Purpose
This is the packaging half of the Phase-1 exit criterion "one-line installer on
Hetzner + Coolify; public AGPLv3 release". All the pieces already exist on disk
(`.env.example`, `generate_keys.sh`, the 681-line production compose with caddy
TLS + all 15 MCP servers, `health_check.sh`, `e2e_verify.sh`) — what is missing
is the **single orchestrating command** that chains them unattended. Lowering
install to one command is what makes the Community Edition self-hostable by a
solo operator who is not a BountyStrike developer.

## Output
- `scripts/install.sh` — unattended bootstrap orchestrator (new)
- `scripts/seed_env.sh` — non-interactive secret seeder (new)
- `scripts/test_install_e2e.sh` — offline test harness w/ stub `docker` (new)
- `.env.example` — reconciled to cover every compose-required no-default secret
- `README.md` — one-line install section + stale-status fix
- `docs/DEPLOYMENT.md` — "Deploy via Coolify" recipe subsection
</objective>

  an existing non-empty value.

## AC-1: Fresh unattended provision
```gherkin
Given a checkout with no .env and no keys/ directory
When I run `bash scripts/install.sh --no-up --unattended`
Then .env is created from .env.example
And POSTGRES_PASSWORD, REDIS_PASSWORD, HATCHET_COOKIE_SECRET,
    HATCHET_POSTGRES_PASSWORD, LANGFUSE_SECRET, LANGFUSE_SALT are all non-empty
And keys/scope_jwt_private.pem (chmod 600) and keys/scope_jwt_public.pem exist
And ANTHROPIC_API_KEY (and the other BYOK keys) remain blank
And the script exits 0
```

## AC-2: Idempotent re-run never clobbers secrets
```gherkin
Given a .env already seeded with infra secrets and an existing keypair
When I run `bash scripts/install.sh --no-up --unattended` a second time
Then every previously-written secret value is byte-identical to the first run
And the keypair files are not regenerated
And the script exits 0
```

## AC-3: Full run brings the stack up and waits for health
```gherkin
Given Docker is available (real or a stub on PATH) and a seeded .env
When I run `bash scripts/install.sh --unattended`
Then the script invokes
    `docker compose -f infra/docker/docker-compose.yml --env-file .env up -d --build`
And it polls health (scripts/health_check.sh) with a bounded retry/timeout
And on success it prints next-steps listing the still-blank BYOK keys and the
    `python scripts/gen_scope_jwt.py ...` scope-JWT command
```

## AC-4: Missing Docker never triggers an implicit curl|sh-as-root (S1) <!-- audit-strengthened -->
```gherkin
Given `docker` is not on PATH
When I run `bash scripts/install.sh` (with or without --unattended, without --install-docker)
Then the script exits non-zero with an actionable message showing the exact
    `curl -fsSL https://get.docker.com | sh` command for the operator to run
And it does NOT auto-execute any `curl ... | sh` itself
When I instead run `bash scripts/install.sh --install-docker --unattended`
Then (and only then) it may run the get.docker.com installer
```
Rationale: piping a remote script to a root shell is the exact risk class this
product hunts. Docker auto-install must be an explicit, separate opt-in
(`--install-docker`), never implied by `--unattended` alone.

## AC-5: Stack never boots on predictable compose-baked secret defaults (M2) <!-- audit-strengthened -->
```gherkin
Given infra/docker/docker-compose.yml bakes `:-` fallback defaults for
    HATCHET_POSTGRES_PASSWORD, HATCHET_COOKIE_SECRET, LANGFUSE_SECRET, LANGFUSE_SALT
    (and requires POSTGRES_PASSWORD, REDIS_PASSWORD with no default at all)
When seed_env.sh runs on a fresh .env
Then every one of those secrets is filled with a fresh random value in .env
    (so the running stack uses the .env value, NOT the hardcoded compose default)
And .env.example contains a placeholder line for each of them
    (incl. HATCHET_POSTGRES_PASSWORD, currently absent)
And no secret in the seeded .env equals the literal compose-baked default string
```
Rationale: a predictable, source-visible default password on hatchet-postgres /
langfuse / hatchet-cookie is a latent vuln; only POSTGRES/REDIS being no-default
made the original "no-default parity" check trivially pass while leaving the
others on shipped defaults.

## AC-7: Secret files are not world-readable (M1) <!-- audit-added -->
```gherkin
Given the host umask is the typical 022 (new files default to 0644)
When install.sh / seed_env.sh write or update .env
Then .env ends with mode 0600 (owner-only)
And keys/ contents keep generate_keys.sh's 0600 on the private key
And no secret-bearing file (.env, .env.backup*) is left group/other-readable
```

## AC-8: Health wait fails loud — never exits 0 on a half-up stack (M3) <!-- audit-added -->
```gherkin
Given install.sh brought the stack up and is polling scripts/health_check.sh
    (which exits 0 healthy / 1 unhealthy / 2 not-running, under `set -e`)
When some service is still unhealthy or not-running after the bounded timeout
Then install.sh captures the health rc without `set -e` aborting the retry loop
And on timeout it exits NON-ZERO naming the still-unhealthy services
And it never prints "install complete" / exits 0 while a service is down
```

## AC-9: Preflight fails clean before writing a partial .env (M4) <!-- audit-added -->
```gherkin
Given a host missing `openssl` (or `bash` too old for the script)
When I run install.sh or seed_env.sh
Then it detects the missing prerequisite and exits non-zero with a clear message
    BEFORE creating or mutating .env
And it never writes a .env with blank/half-filled secrets
And after a successful seed, `docker compose --env-file .env config -q` succeeds
    (generated secret values round-trip through compose interpolation)
```

## AC-10: Mixed-state .env — fill only the blanks, never touch operator values (S4) <!-- audit-added -->
```gherkin
Given a .env where POSTGRES_PASSWORD is already set by the operator but
    LANGFUSE_SALT is empty
When seed_env.sh runs
Then LANGFUSE_SALT is filled with a fresh value
And POSTGRES_PASSWORD (and every other already-set value) is byte-identical after
```

## AC-6: Offline test harness green + package still verifies
```gherkin
Given no Docker daemon (a stub docker shim on PATH)
When I run `bash scripts/test_install_e2e.sh`
Then all cases pass and it exits 0
And `bash scripts/e2e_verify.sh` still passes (deployment package intact)
```
