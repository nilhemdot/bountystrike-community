<objective>
## Goal
Wire the already-built `TokenBucketLimiter` (mcp/politeness-mcp) into the recon
pipeline's in-process egress path so every reflection-probe HTTP GET is gated by
a per-host token bucket with adaptive 429/503 backoff — closing the one
unbounded network path in recon and activating the dead `ScopeFilter.rps_for_host`
per-host override.

## Purpose
PROJECT.md mandates network-layer politeness ("Scope enforcement at network
layer (tap0 egress)"). The recon pipeline (subfinder→httpx→katana) already
self-limits its out-of-process ProjectDiscovery binaries via each tool's
`-rate-limit` flag. But the in-process reflection prober (`_check_reflection`
→ `HttpxReflectionProber.probe`) fires one raw `httpx` GET per `xss-candidate`
parameter with **no rate limiting at all** — across many hosts, this can hammer
a target. The `TokenBucketLimiter` (per-host bucket + 429/503 adaptive backoff,
fully tested in mcp/politeness-mcp/tests/test_bucket.py) is the purpose-built
fix but is not imported anywhere. This is the same posture as 01-06: the
component is built and field-tested — WIRE it, do not rebuild.

## Output
- `politeness-mcp` added as a control-plane workspace dependency.
- `HttpxReflectionProber` extended to optionally gate each GET through a
  `TokenBucketLimiter` (acquire-before / report-after), backward-compatible.
- `domains/recon/__main__.py` constructs one limiter per recon run and injects
  it, with `ScopeFilter.rps_for_host` as the per-host rate resolver.
- New `control-plane/tests/test_recon_politeness.py` — deterministic, no real sleep.
</objective>

## Verified facts (planning recon, 2026-05-31)
- `TokenBucketLimiter` public API: `acquire(host, rps_limit=None) -> {host, waited_s,
  would_wait_s, granted}`; `report(host, status_code, latency_ms=None)`; `status(host)`.
  Constructor: `TokenBucketLimiter(default_rps=5.0, time_source=None, sleep_fn=None)`.
  `time_source`/`sleep_fn` are injectable → tests run with a manual clock, no real sleep.
  Module imports only asyncio/time (import-light; safe for probers.py's light import graph).
- `acquire` returns `granted=False` (no token consumed, no sleep) when projected wait
  exceeds `MAX_WAIT_SECONDS` (30s). On 429/503, `report` sets `backoff_until = now+60s`
  and halves the effective refill rate. `MAX_RPS_CEILING = 50.0` caps malformed-JWT rps.
- `ScopeFilter.rps_for_host(host) -> int` returns `relaxed_hosts.get(host.lower(),
  default_rps)`. It is currently UNUSED in service.py (`default_rps` is passed globally).
  Wiring the bucket through it is what makes the per-host override live.
- `HttpxReflectionProber.probe(url, parameter, sentinel) -> bool` owns its own
  `httpx.AsyncClient().get(url)` and therefore owns the response `status_code` — so
  acquire+report belong INSIDE the prober (it is the only place with the status code).
- Root `[tool.uv.workspace]` already lists `mcp/politeness-mcp`; only `[tool.uv.sources]`
  + control-plane `dependencies` need the entry. Mirror the 01-06 `oracle-mcp` wiring.
- `__main__.py` composition root builds `scope_filter`, `runner`, `persistence`,
  `prober = HttpxReflectionProber()`, then `ReconService(...)`. The limiter is
  constructed and injected here — `ReconService.run` and the `ReflectionProber`
  Protocol are NOT changed (gating lives inside the concrete prober).

## AC-3: Per-host rate override (relaxed_hosts) is honoured
```gherkin
Given a scope JWT with rate_limits.default_rps=5 and relaxed_hosts={"fast.example.com": 20}
When the prober probes fast.example.com and then slow.example.com
Then the bucket created for fast.example.com has rps_limit=20

```

## AC-4: 429/503 triggers adaptive backoff
```gherkin
Given a host returns HTTP 429 on a probed GET
When limiter.report(host, 429) is applied
Then the host bucket is in backoff (effective refill rate halved for the backoff window)
And a subsequent acquire for that host reflects the reduced rate
```

## AC-5: Wait-cap exhaustion FAILS OPEN (never silently buries a real bug) <!-- audit-added M1 -->
```gherkin
Given a host bucket is exhausted such that acquire's projected wait exceeds MAX_WAIT_SECONDS
When the prober attempts to probe that host
Then acquire returns granted=False with NO GET issued
And probe returns True (candidate KEPT — the deterministic oracle is the real gate; our own
     rate-limiting must never drop a potential finding as if it were unreflected)
And a structured WARNING (recon.politeness.probe_skipped, host, url) is logged for audit reconstruction
```

## AC-7: Per-host rps is clamped to the bucket ceiling <!-- audit-added S1 -->


## SCOPE LIMITS
- "Token-bucket only" (confirmed at planning): wire the existing limiter into the
  in-process reflection-prober egress path. No new recon pipeline stages.
- DEFERRED to Phase 2: `dnsx` (DNS resolution) and `naabu` (port-scan) pipeline
  stages named in the ROADMAP scope line — not implemented here.
- DEFERRED: applying the token bucket / relaxed_hosts batching to the out-of-process
  ProjectDiscovery binaries (subfinder/httpx/katana keep their `-rate-limit` flag
  self-limit). An in-process bucket cannot throttle a binary's internal request loop
  token-by-token; revisit if/when recon moves fully in-process.
- No Hatchet recon task (recon is launched by orchestrator `_phase_recon` as a
  subprocess; durable-task wrapping is out of scope).
- No Redis/multi-process bucket backend (single-process recon container; bucket
  docstring already notes the Redis swap path for SaaS).
- No new dependencies beyond the politeness-mcp workspace member.

## DOCTRINE (audit-added)
- FAIL-OPEN: the politeness gate may only DELAY or SKIP a probe, never silently
  discard a candidate. On skip/limiter-error the candidate is KEPT (probe→True)
  and a WARNING logged — the deterministic oracle (01-06) remains the sole gate
  that can reject a finding. Throttling must never bury a real bug.
- Per-host bucket key = lowercased hostname only (never URL/netloc-with-path).
- rps passed to acquire is always clamped to MAX_RPS_CEILING.
